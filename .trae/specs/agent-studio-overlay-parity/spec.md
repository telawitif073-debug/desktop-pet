# 桌宠全面对齐与创作增强 PRD（桌面端对齐手机端 · 悬浮窗优化 · 逻辑治理）

## Overview

- **Summary**：以本轮 GitHub 同类项目调研与双端代码全量盘点为依据，完成四件事：①调研结论产品化；②双端现有逻辑治理与反复优化；③安卓模拟器实测并优化系统悬浮窗宠物；④把手机端每个页面的现有功能在桌面端完整实装并优化，且桌面端提供比手机端更全面的「创作」能力。
- **Purpose**：手机端（RN 0.87）经多轮迭代已显著领先桌面端（Electron 44）：智能体档案模型、定时任务、联网/技能、reasoning、三引擎音色、音色商店等均只在手机端；桌面悬浮宠物在多显示器、边界、缩放等基线能力上有明确缺陷；安卓系统悬浮窗交互单薄。本轮要收敛双端差距，并让桌面端成为「功能最全的创作端」。
- **Target Users**：桌面端日常养宠/创作用户（重创作、重多窗口交互）；手机端随身用户（悬浮窗陪伴）；两端登录同一账号经平台云同步共享配置。

## Goals

- **G1 调研转化**：GitHub 调研（18+ 桌面项目、3 个手机悬浮项目，star/许可证 2026-09-25 实查）结论转化为可执行需求；调研过程本身已完成，证据保存在本次会话记录。
- **G2 逻辑治理**：修复盘点发现的桌面端死链路/窗口缺陷，双端主动消息与语音的队列治理；所有移植以「对齐+顺手优化」为原则，不做无证据的大重构。
- **G3 悬浮窗优化（安卓）**：在雷电模拟器实测现有悬浮窗全部行为并留证，按问题清单优化：交互菜单、边界/尺寸、保活引导、运行时离线可用性。
- **G4 桌面功能对齐手机端**：逐页对齐（登录注册、聊天/智能体管理、设置、审核/商店），覆盖数据模型、对话运行时、定时任务、主动对话、联网/技能、音色三引擎、云同步。
- **G5 桌面创作增强**：桌面端提供原生「创作中心」——比手机端更全面的智能体编辑、动作创作与互动绑定、音色创建与发布、资源打包安装/上传。

## Non-Goals

- **不做 iOS 系统悬浮窗**（平台无此能力，维持 App 内陪伴现状）。
- **不做 Tauri 迁移、不换渲染技术栈**（调研确认 Electron 对重功能项目仍是主流）。
- **不做多智能体可视化编排画布、插件沙箱 SDK、`/state` agent 协议、llama.cpp 本地端侧模型、SillyTavern 角色卡、在线模型转换工具**（列入 P2 路线，本轮最多预留数据兼容）。
- **不做付费/商业化/多语言**。
- **后端以复用为原则**：voices、tools（天气/股票/足球）、multi-chat、sync、agents/pets 审核接口均已存在，本轮不为桌面端新建重型模块；仅在发现缺口时最小增补（如音色审核视图）。
- **不恢复已被用户明确删除的 AI 生成视频/AI 生宠链路**（保留平台上传页既有「AI 扣取」面板）。

## Background & Context

### 盘点结论（关键事实，附证据位置）

- **桌面端**（Electron 44 + React 19 + Pixi v8 + three + Vite/Forge；透明置顶无边框主窗 + 商店网页窗）：
  - `LlmProfile` 仅 6 字段（id/name/apiKey/baseUrl/model/systemPrompt，[config.ts L16-L25](file:///e:/desktop-pet/src/main/config.ts#L16-L25)），聊天历史单例 20 条（conversationManager），无多档案消息隔离。
  - 无定时任务、无联网搜索、无平台技能、无 reasoning 展示、气泡纯文本无 Markdown、主动对话仅全局一档（10 分钟下限、8-22 点）。
  - TTS 仅 Edge TTS + Web Speech 回退；无云 TTS、无 GPT-SoVITS、无音色库/绑定/发布；登录依赖商店窗网页且仅密码登录，无 refresh token 轮换。
  - 悬浮窗口缺陷（盘点实证）：拖拽**全程无边界钳制**可甩到任意位置（[main.ts petDragTick](file:///e:/desktop-pet/src/main.ts#L606-L615)）；多显示器支持弱——初始定位、面板开合（650×450）、wander、截屏全部写死主显示器，宠物在副屏时开面板会跳回主屏；不支持滚轮缩放（仅设置页滑杆，改动会整体销毁重建渲染器）。
  - 死链路/遗留：`chat:greeting-trigger` 主进程从不发送、渲染端有监听；[src/renderer.ts](file:///e:/desktop-pet/src/renderer.ts) 为未被引用的旧入口。
  - 桌面独有优势（保留并作为增强底座）：像素级点击穿透、随机漫步、桌面截屏/录屏/摄像头持续感知、sherpa-onnx 本地唤醒与连续聆听、多图视觉输入、Live2D Cubism/GLTF 本地完整渲染、live2d-lite 自研分层动画、帧/clip 动作系统与 AI 关键帧基础、便携平台三件套拉起。
- **手机端**（RN 0.87；4 屏 + 抽屉商店 + 安卓原生悬浮服务）：
  - 完整 `LlmProfile`（头像/简介/领域标签/角色/风格/欢迎语/示例问题/能力/专属音色/严格形象绑定）、ProfileManager（搜索/启停/复制/级联删除/导入导出/人设卡/批量导入+能力确认）。
  - `[[TASK|…]]` 定时任务协议 + 中文时间解析 + 调度器（15s tick/2h GRACE/每日上限/重复顺延）；`[[SEARCH|…]]` 三供应商两阶段回路；`[[WEATHER|STOCK|FOOTBALL|…]]` 平台免费技能；按档案能力（proactive/tasks/web/…）驱动。
  - reasoning_content 流式分流 + ThinkCard 计时 + 思考语言强制；自写 MarkdownText；失败气泡重试。
  - 音色：系统 TTS / OpenAI 兼容云 TTS / GPT-SoVITS，音色库下载安装、试听、删除、每智能体 `boundVoiceId`、失败逐级降级；音色发布（Key 正则拦截）。
  - 悬浮窗：`OverlayPetService.kt`（TYPE_APPLICATION_OVERLAY + 前台服务常驻通知 + WebView 180dp + 拖拽 8dp slop + 点击 bounce），[overlay.html](file:///e:/desktop-pet/mobile/android/app/src/main/assets/overlay.html) 支持 image/pack(canvas)/live2d/3D，但 **Live2D/three 运行时从 unpkg CDN 加载（离线不可用）**；系统悬浮窗无菜单/无喂食/无消息气泡/尺寸固定。
- **平台后端**（NestJS + PG）：auth 邮箱验证码/双令牌、pets/agents/voices 资源与审核、tools 代理、multi-chat 编排、sync（config/pet-state/chat-history/library，apiKey 加密）、app-update 热更——桌面端可直接复用。

### 调研结论（对本项目直接生效的部分）

- 「一套 Web 渲染核心 + 多端壳」已被 airi（49.4k★，Web/Electron/Capacitor）与 Stardust（安卓 WebView 悬浮 + Tauri 桌面）验证，本项目 overlay.html 双端复用路线正确，继续。
- 桌宠基线（PPet 2.0k★ 等同源栈核对）：置顶/穿透/拖动/**Ctrl 滚轮缩放**/托盘/开机自启/自动更新应齐备——本机缺滚轮缩放、托盘菜单、开机自启、自动更新。
- DyberPet（983★）：通知合并 + 语音优先级队列、锁屏暂停数值、JSON 声明式资源包；openpets（1.2k★）：插件只接收高层情绪/事件、不接触对话原文；LingChat（2.3k★）：LLM 输出→情绪分类→表情/动作中间层。本轮采用「消息/语音队列治理」，情绪引擎列 P1。
- AI-Live-Overflow（68★，安卓 WebView 悬浮蓝图）：长按/双击/连击彩蛋、Fling 甩回、常驻通知+电池白名单+国产 ROM 自启引导、透明 WebView 必须在 loadUrl 前 setBackgroundColor(0)、CSS 动画只用 transform。
- 许可证红线：GPL/AGPL 项目（live2d-widget、clawd、LingChat、MiniCPM）代码不可拷贝；只从 MIT/Apache 类（airi、BongoCat、VPet、PPet、openpets、ChatWaifu_Mobile）借鉴设计。
- UGC 趋势（VPet Workshop / BongoCat Awesome / Codex Pet 帧宠生态）：动作包/台词包/角色卡类目、在线转换工具列 P2；本轮桌面先做本地资源打包与音色发布。

## Functional Requirements

### A. 逻辑治理（G2）

- **FR-1（桌面基线修复）**：① 删除 `chat:greeting-trigger` 死链路与未被引用的 `src/renderer.ts`；② 拖拽边界钳制到宠物**当前所在显示器** workArea（保留固定宽高防 DPI 撑窗）；③ 面板开合、wander 边界、主动截屏改为跟随宠物所在显示器（副屏开面板不再跳回主屏）；④ Ctrl/Alt + 滚轮在宠物模式下等比缩放窗口（200–600，复用 applyWindowSize，不重建渲染器），即时持久化。
- **FR-2（消息与语音队列治理，双端）**：建立统一优先级——用户正在对话 > 到点任务 > 状态提醒 > 周期主动；任意时刻只播放一条 TTS，新主动消息不打断用户正在进行的对话朗读；同类主动消息 60s 内去重。手机端把任务到点、状态提醒、proactive 三类入口纳入同一条发送/朗读队列；桌面端同步实现。
- **FR-3（手机悬浮运行时离线化）**：overlay.html 的 Live2D（pixi + pixi-live2d-display + cubism core）与 three 运行时改为 App 内置 assets 本地加载（不依赖 unpkg），无网络时已安装的 live2d/3D 宠物悬浮窗可正常显示；确需保留 CDN 时必须有本地兜底且默认走本地。

### B. 安卓悬浮窗实测与优化（G3）

- **FR-4（实测基线）**：在雷电模拟器（1080×1920，adb 127.0.0.1:5555）对系统悬浮窗逐项实测并截图留证：权限引导（未授权→系统设置页）、开启/关闭、前台服务常驻通知、拖拽、点击、image/pack/live2d/3D 四形态渲染、重启 App/服务后状态、与 App 内当前宠物的一致性。
- **FR-5（悬浮窗交互增强）**：在系统悬浮宠物上提供与 App 内 FloatingPet 对齐的操作：**长按（≥500ms）呼出环形/竖排菜单**（喂食、玩耍、休息、打开 App、关闭悬浮窗），菜单项直接改宠物四维状态并回写 store/云同步；点击保留 bounce；拖拽与点击/长按手势不冲突（8px slop）。
- **FR-6（悬浮窗稳健性）**：① 宠物可拖到但不可完全甩出屏幕（至少保留可见边距）；② 新增悬浮窗尺寸三档（小/中/大，约 120/180/260 dp）设置，记忆选择；③ 开启悬浮窗时如遇国产 ROM 常见后台限制，展示电池白名单/自启动引导文案（可跳转应用详情页）；④ 通知渠道与 Android 13+ 通知权限兼容（现状已声明权限，补运行时申请）。
- **FR-7（P1：悬浮窗消息气泡）**：主动消息/任务到点时悬浮宠物上方展示短气泡（数秒自动消失，点击打开 App），不遮挡触摸；带 TTS 时受 FR-2 队列约束。

### C. 桌面端对齐手机端（G4）

- **FR-8（数据模型与消息隔离）**：桌面 `LlmProfile` 对齐手机端全部字段（avatar/intro/domainTags/role/style/greeting/exampleQuestions/enabled/capabilities/webSearch/boundVoiceId/petAssetId），旧 config.json 自动迁移；聊天历史按档案 id 隔离存储，切换档案切换历史与当前宠物（沿用「智能体严格绑定一个已下载形象」规则）；云同步 config/pet-state/chat-history 载荷与手机端口径一致（含音色库、按档案消息）。
- **FR-9（智能体管理与编辑器）**：桌面提供智能体列表（搜索/启停/复制/删除/级联消息/激活切换/绑定形象）与完整编辑表单（手机端全部字段 + 领域/角色/风格预设 chip + 欢迎语 + 示例问题 + 能力开关与规格 + 专属音色选择 + API Key/baseUrl/model）；支持 JSON/YAML 子集与人设卡（agent_name/persona）粘贴导入、单/批量导入（同名合并保留本地 Key 与绑定）、导出（剥 apiKey/id/本机偏好）。
- **FR-10（对话体验对齐）**：桌面聊天气泡支持 Markdown（行内/代码块/列表/引用/链接，零重依赖方案与手机端口径一致）；reasoning_content 流式分流、可折叠思考卡与思考耗时、显示思考开关与思考语言 auto/zh/en；失败消息一键重试；空态显示 greeting + 示例问题；流式中断自动重试一次等既有手机端容错策略同步。
- **FR-11（能力运行时对齐）**：桌面主进程/渲染端移植手机端纯逻辑能力：① `[[SEARCH|q]]`（bocha/serper/tavily 三供应商，按档案 Key，最多 3 轮工具回路）；② `[[WEATHER|STOCK|FOOTBALL]]` 走平台 tools（登录态）；③ 能力按智能体开关与 spec（intervalMinutes/wakingHours/exampleTasks/maxActiveTasksPerDay/web provider）；工具失败不中断对话、模型不得编造未返回资料。
- **FR-12（定时任务）**：移植中文自然语言时间解析与任务系统：相对时间/每天/每周/明早明晚/时段+点/半刻三刻、过点顺延、90 天上限、同刻防重、pause/resume/cancel/query 聊天内意图；到点经平台/LLM 生成提醒消息并按 FR-2 队列送达；App 未运行期间不补发（重开后过期任务按 2h GRACE 规则处理）；任务随档案云同步。
- **FR-13（按档案主动对话）**：主动对话由「全局一档」升级为「按智能体能力」：proactive 能力开关、间隔（下限 5 分钟）、wakingHours（默认 8-22）、用户静默窗口、回前台重置、inFlight 防重；保留低状态（饥饿/精力/心情 <30）提醒。
- **FR-14（音色三引擎与音色库）**：桌面 TTS 在保留 Edge TTS/系统语音的基础上新增：OpenAI 兼容 `/audio/speech`（engine/baseUrl/apiKey/model/instructions/speed）、GPT-SoVITS `/tts`（refAudioPath/promptText/textLang + 8s 连接测试）；音色库支持从平台 voices 列表浏览/试听/下载/删除/启用；朗读优先级 = 智能体 boundVoiceId → 全局云音色 → Edge/系统，任一失败逐级降级；语速/音调/音量沿用。
- **FR-15（账号与商店对齐）**：桌面壳内（创作中心/商店）提供邮箱+验证码注册/登录与验证码登录、双令牌与 401 单飞刷新重放（对齐手机端 platform 客户端口径）；商店可浏览/安装音色资源；平台 Web 上传页新增「发布音色」（三模式：OpenAI 兼容/GPT-SoVITS/粘贴 JSON；提交前配置校验、apikey/secret/token 字段正则拦截、样本仅接受 http(s) 音频直链 ≤5MB），管理端可审核音色。
- **FR-16（心情联动）**：桌面每轮有效对话后好感度 +1；开启「聊天影响心情」时按正负词正则 ±8；开关关闭时四维状态维持现状规则（关闭项归 80）。

### D. 桌面创作增强（G5，要求「比手机端更全面」）

- **FR-17（创作中心窗口）**：新增 Electron 原生普通窗口「创作中心」（复用同一份 renderer，hash 路由独立视图；不走网页、不依赖平台三件套在线），包含三个工作区：**智能体**（FR-9 全部，桌面宽屏提供左右分栏：列表 ↔ 编辑器 ↔ 实时预览欢迎语/示例问题/人设拼装结果）、**动作**、**音色**。
- **FR-18（动作创作增强）**：在现有「上传 1–30 帧、≤15 个、可播放/删除」基础上：① 提供喂食/休息/玩耍/无 的互动绑定 UI（不再只能靠资源包 interaction 写入）；② 帧排序拖拽、帧率调节（1–24fps）、逐帧删除、循环/单次设置；③ 动作名/互动重复校验；④ 本地帧序列可一键「打包为宠物附带动作 zip」并跳转上传或直接本地保存。
- **FR-19（音色创建/发布桌面端）**：创作中心音色工作区支持三模式新建音色配置、试听与连接测试、样本音频选择、填写名称/简介后直接发布到平台（复用 FR-15 同一后端与安全校验）；可查看「我发布的音色」与审核状态。
- **FR-20（本地资源打包安装）**：桌面选择本地图片（单图/多图/gif）打包为符合平台契约的宠物包（`main.*` + 可选 manifest/animations），支持「直接本地安装切换」或「去网页发布」；包格式与手机端/平台 resolveFormat 完全兼容（image/pack/live2d/model3d 判定一致）。
- **FR-21（P1：创作增强续）**：情绪引擎（回复文本→6–8 类情绪→Live2D 表情参数/动作映射，先覆盖真 Cubism 与帧动画）；台词/动作 JSON 声明式编辑；托盘菜单 + 开机自启 + electron-updater（复用 /api/app-update 通道思路，桌面独立资源 URL）。

## Non-Functional Requirements

- **NFR-1 质量门**：每个切片完成时 `npx tsc --noEmit` 三工程（仓库根、mobile、platform/backend、platform/frontend 涉及者）全绿；桌面 `npm run test`（vitest）通过且新增纯逻辑（时间解析/工具回路/合并导入/队列）补单测；ESLint 无新增 error。
- **NFR-2 证据门**：手机端改动必须实发热更并走完整证据链（本地包特征对比 → scp → 外部 HTTP manifest/zip → 服务器 zip 复查 → 模拟器干净冷启动横幅）；桌面改动必须 `npm start` 实测关键路径并截图/日志留证；悬浮窗改动必须模拟器逐项截图。禁止「只在 dev 看过」即宣称完成。
- **NFR-3 兼容与迁移**：旧 config.json、旧 AsyncStorage 持久化、旧云同步载荷必须平滑迁移，不丢用户配置/历史/Key；空库/新设备首次登录恢复行为与手机端一致。
- **NFR-4 安全**：apiKey/凭证永不进入导出文件与音色发布 payload；音色发布 Key 字段拦截双端一致；平台请求 401 单飞刷新不踩踏；Electron 上下文隔离/自定义协议白名单维持现状不放松。
